# Security VPN

> Безопасность личных данных превыше всего

VPN-сервис с регистрацией: свой сервер на Aeza (Ubuntu 24.04) и приложение для Windows. Протокол: VLESS + Reality (Xray).

```
Windows-приложение ──HTTPS :8443──▶ PHP API ──▶ MariaDB   (регистрация, вход, пароли в виде хешей)
        │                                │
        └──── VLESS + Reality :443 ──────┴──▶ Xray ──▶ интернет
```

Пользователь регистрируется в приложении, сервер выдаёт ему личный UUID и добавляет его в Xray (до ~15 секунд). Адрес сервера, логин и пароль SSH в приложение не вводятся: они нужны только тебе, чтобы один раз поставить сервер.

## Структура

| Папка | Что внутри |
|---|---|
| `api/` | PHP-API: регистрация, вход, смена пароля, выдача параметров подключения (развитие твоих `index.php` / `profile.php`) |
| `server/` | `install.sh` (установка всего на сервер), `sync-xray.php` (пользователи из базы в Xray), конфиги nginx и systemd |
| `app/` | Windows-приложение: C# (WPF + WebView2), интерфейс в `app/Web` (HTML/CSS/JS, планета на canvas) |

## Шаг 1. Залить в git

Создай пустой репозиторий на GitHub (лучше приватный) и в папке проекта:

```bash
git init
git add .
git commit -m "Security VPN: первая версия"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/security-vpn.git
git push -u origin main
```

Секреты в git не попадают: `app/config.json`, ключи и сертификаты в `.gitignore`.

## Шаг 2. Сервер

Подключись к серверу (`ssh root@IP`) и выполни:

```bash
apt-get update && apt-get install -y git
git clone https://github.com/ТВОЙ_ЛОГИН/security-vpn.git
cd security-vpn
bash server/install.sh
```

Приватный репозиторий проще не клонировать, а скопировать с компьютера: `scp -r security-vpn root@IP:/root/`.

В конце установщик напечатает блок вида:

```json
{ "apiUrl": "https://IP:8443", "certSha256": "A9:F5:CC:..." }
```

и код приглашения для регистрации. **Сохрани их**, они понадобятся на шаге 3. Если у Aeza включён внешний фаервол, открой порты `443/tcp` и `8443/tcp`.

Проверка: `curl -k https://127.0.0.1:8443/api/info` на сервере должен вернуть JSON.

## Шаг 3. Приложение (Windows 10/11)

Нужно: [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0), Git, VS Code с расширением «C# Dev Kit». WebView2 Runtime уже есть в Windows 11 и в обновлённой Windows 10.

```powershell
git clone https://github.com/ТВОЙ_ЛОГИН/security-vpn.git
cd security-vpn\app
powershell -ExecutionPolicy Bypass -File .\get-xray.ps1   # скачает ядро Xray в app\core
copy config.example.json config.json                       # впиши apiUrl и certSha256 с сервера
dotnet run
```

В VS Code: `File → Open Folder → security-vpn\app`, затем `F5`.

Готовый exe: `dotnet publish -c Release -r win-x64 --self-contained false -o publish`, запускать `publish\SecurityVPN.exe`.

### Проверить окно приложения без сервера

В папке `app` выполни `dotnet run -- --demo`. Откроется настоящее окно Windows с демо-интерфейсом: вход с любым логином и паролем от 8 символов, код приглашения `demo`, кнопка имитирует подключение. Файл `config.json` и ядро Xray для этого не нужны.

### Посмотреть дизайн без сервера

Открой `app/Web/index.html` через расширение VS Code «Live Server» (или просто в браузере). Включится демо-режим: вход с любым логином и паролем от 8 символов, код приглашения `demo`. Так удобно править внешний вид.

## Проверить, что работает

1. Зарегистрируйся в приложении (логин, пароль от 8 символов, код приглашения).
2. Нажми большую кнопку. Через несколько секунд статус станет «Вы защищены».
3. Открой в браузере любой сайт «мой IP»: должен показаться IP твоего сервера.
4. Нажми кнопку снова: прокси Windows вернётся к прежним настройкам.

## Если что-то не так

| Сообщение | Что проверить |
|---|---|
| «Не удалось связаться с сервером» | `apiUrl` в `config.json`; порт 8443 открыт; `systemctl status nginx` |
| «Сертификат сервера не совпал» | `certSha256`: скопируй заново из вывода `install.sh` (или `openssl x509 -noout -fingerprint -sha256 -in /etc/securityvpn/tls/cert.pem`) |
| «Не найдено ядро VPN» | запусти `get-xray.ps1` |
| «Сервер не отвечает» при подключении | порт 443 открыт; `systemctl status xray`; `journalctl -u xray -n 50` |
| «Сервер ещё применяет настройки» | `systemctl status securityvpn-sync.timer`; `journalctl -u securityvpn-sync -n 30` |
| Пропал интернет после аварийного закрытия | запусти приложение ещё раз (оно вернёт прокси) или выключи прокси в «Параметры → Сеть → Прокси» |

## Важно знать

- **Системный прокси.** Приложение включает прокси Windows. Браузеры и большинство программ его учитывают, а часть программ (некоторые игры и клиенты) нет. Режим TUN, который заворачивает весь трафик, это следующий этап.
- **Регистрация защищена кодом приглашения** (`invite_code` в `/etc/securityvpn/api.json`). Пустая строка делает регистрацию открытой для всех; тогда любой, кто найдёт порт, сможет пользоваться твоим сервером и трафиком.
- **Новый пользователь = перезапуск Xray** (около секунды обрыва у уже подключённых). Для небольшой компании это нормально.
- **Безопасность сервера.** Смени пароль root из письма Aeza и переходи на вход по SSH-ключу. Пароль root нигде не хранится и в git не попадает.
- **Ответственность.** Если дашь доступ другим людям, их трафик идёт с твоего сервера. Учитывай правила Aeza и законы своей страны.

## Что проверено и что нет

Проверено на Linux: PHP-API на реальной MariaDB (все эндпоинты, лимиты попыток), конфиг Xray из `sync-xray.php` (`xray run -test`), туннель VLESS + Reality между конфигом сервера и C#-клиентом (трафик прошёл, статистика читается), закрепление сертификата в `ApiClient`, весь сценарий интерфейса в демо-режиме, разбор ключей в `install.sh`.

Не проверено (нужен Windows и реальный сервер): запуск окна WPF/WebView2, работа с системным прокси Windows, полный прогон `install.sh` на чистой Ubuntu. Если что-то из этого упадёт, пришли текст ошибки, и я поправлю.
